# svoyaki_messenger
## 1. Требования к системному окружению

Для успешного развертывания и запуска всех компонентов системы на локальном компьютере разработчика или администратора должны быть установлены следующие программные пакеты:

1. **Docker & Docker Compose** (версии 20.10+ и 2.0+ соответственно) — для контейнеризации и быстрого развертывания СУБД PostgreSQL в изолированном окружении.
    
2. **Go (Golang)** (версии 1.20 и выше) — среда компиляции и исполнения серверной части мессенджера.
    
3. **Goose** — консольная утилита для автоматического управления и применения миграций базы данных.
    
4. **Современный веб-браузер** (Google Chrome, Mozilla Firefox, Apple Safari или Microsoft Edge последних версий) с поддержкой стандартов HTML5, CSS3, JavaScript ES6 и протокола WebSocket.
    

## 2. Предварительная проверка окружения

Перед началом установки убедитесь, что все необходимые утилиты доступны в системной переменной `PATH`. Для этого откройте терминал (командную строку) и выполните команды:

Bash

```
# Проверка версии Docker
docker --version

# Проверка версии Docker Compose
docker-compose --version

# Проверка установленной версии Go
go version

# Проверка наличия утилиты goose
goose --version
```

_Примечание:_ Если утилита `goose` не установлена, ее можно инсталлировать с помощью встроенного пакетного менеджера Go, выполнив следующую команду:

Bash

```
go install github.com/pressly/goose/v3/cmd/goose@latest
```

Убедитесь, что директория `$GOPATH/bin` (или `%USERPROFILE%\go\bin` на ОС Windows) добавлена в переменную окружения `PATH`.

## 3. Пошаговая инструкция по развертыванию и запуску

### Шаг 1. Развертывание базы данных PostgreSQL в Docker

Сервер базы данных функционирует в изолированном Docker-контейнере. Настройки конфигурации описаны в файле `docker-compose.yml` в корневой директории проекта.

1. Перейдите в корневую директорию проекта, где расположен файл `docker-compose.yml`:
    
    Bash
    
    ```
    cd /путь/к/проекту/svoyaki_messenger
    ```
    
2. Выполните запуск контейнера СУБД в фоновом (демонизированном) режиме:
    
    Bash
    
    ```
    docker-compose up -d
    ```
    
3. Убедитесь, что контейнер успешно запустился и занял сетевой порт `5433` на хост-машине:
    
    Bash
    
    ```
    docker-compose ps
    ```
    
    В выводе терминала статус контейнера базы данных должен быть указан как `Up` или `Running`.
    

### Шаг 2. Инициализация структуры базы данных (Накатывание миграций)

Для автоматического создания необходимых таблиц (`users`, `chats`, `chat_members`, `messages`, `message_reads`), индексов и внешних связей используется механизм миграций `goose`.

1. Находясь в корневой папке проекта, выполните команду применения миграций:
    
    Bash
    
    ```
    goose -dir back/migrations postgres "postgres://messenger_user:secretpassword@localhost:5433/messenger_db?sslmode=disable" up
    ```
    
2. В терминале отобразится лог успешного выполнения каждого SQL-скрипта:
    
    Plaintext
    
    ```
    goose: migrating db at postgres://messenger_user:secretpassword@localhost:5433/messenger_db?sslmode=disable
    OK    00001_create_users_table.sql (12.4ms)
    OK    00002_create_chats_table.sql (10.1ms)
    OK    00003_create_chat_members_table.sql (15.3ms)
    OK    00004_create_messages_table.sql (11.8ms)
    ```
    
    С этого момента база данных полностью готова к работе и приёму транзакций.
    

### Шаг 3. Запуск серверного приложения (Go Backend)

1. Перейдите в директорию, содержащую исходный код бэкенда мессенджера:
    
    Bash
    
    ```
    cd back
    ```
    
2. Подтяните и верифицируйте все внешние зависимости проекта (включая JWT и Gorilla WebSocket):
    
    Bash
    
    ```
    go mod tidy
    ```
    
3. Запустите сервер:
    
    Bash
    
    ```
    go run main.go
    ```
    
4. При успешном старте в консоли появятся следующие информационные сообщения:
    
    Plaintext
    
    ```
    [INFO] Успешное подключение к PostgreSQL на порту 5433.
    [INFO] HTTP-сервер мессенджера запущен на порту :8080.
    ```
    
    _Не закрывайте данное окно терминала_, так как в нем отображаются логи запросов и WebSocket-соединений в реальном времени.
    

### Шаг 4. Запуск клиентской части (Frontend)

Клиентская часть приложения представляет собой статический набор файлов (`index.html`, `app.js`, `style.css`), взаимодействующих с API через асинхронные HTTP-запросы и протокол WebSocket.

1. **Способ 1 (Простой):** Откройте файл `front/index.html` в любом современном веб-браузере двойным щелчком мыши.
    
2. **Способ 2 (Рекомендуемый для разработки):** Для корректной обработки сетевых путей запустите локальный статический сервер в папке `front`. Например, с помощью Python:
    
    Bash
    
    ```
    cd front
    python -m http.server 3000
    ```
    
    После этого откройте браузер по адресу: `http://localhost:3000`.
